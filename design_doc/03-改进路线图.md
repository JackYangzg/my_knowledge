# 03 — 改进路线图

> 任务分 P0 / P1 / P2 三档。每个任务标 **dual-scale effort**（人类/CC）。
> 关键：每条任务都对应 `02-七维度评审.md` 中的具体发现。

## P0 — 阻断可发布质量（建议单一 PR，~2 人天）

### P0-1：建立 design token 体系（颜色 + 字体 + 间距 + 形状）

**目标**：把当前 30+ 硬编码颜色、13+ 硬编码字号、15+ 硬编码间距抽到 `ui/theme/` 下。

**步骤**：
1. 新增 `ui/theme/SemanticColor.kt`：定义 `Brand/Primary = #147EC5` / `Text/Primary = #0F172A` / `Bg/Page = #F7FBFF` / `Semantic/Error = #DC2626` / `Semantic/Warning = #EA580C` / `Semantic/Success = #16A34A` 等命名。
2. 新增 `ui/theme/Type.kt`：补全 13 个 M3 typography token，定义 `caption/body/section/title/display` 5 档语义映射。
3. 新增 `ui/theme/Spacing.kt`：定义 `xs(4)/sm(8)/md(12)/lg(16)/xl(20)/2xl(24)/3xl(32)/4xl(48)` 命名。
4. 新增 `ui/theme/Shape.kt`：定义 `small(8)/medium(12)/large(16)` corner radius。
5. 修改 `Theme.kt`：在 M3 `ColorScheme` 之外，定义 `LocalPalette`、`LocalSpacing` 等 `CompositionLocal`。
6. 在 Composable 中以 `LocalPalette.current.brand` 取代 `Color(0xFF147EC5)`，以 `LocalSpacing.current.lg` 取代 `Modifier.padding(16.dp)`。
7. 一次性批量替换（可通过 IDE regex + 手动校验关键位置）。

**对应发现**：
- `02-七维度评审.md` Pass 5（设计系统一致性 2/10）
- `02-七维度评审.md` Pass 4（品牌不识别）
- `01-系统盘点.md` §4 量化清单

**估算**：人类 ~10h / CC ~30min（机械替换）+ ~4h 校验。
**风险**：替换 1000+ 处，可能漏掉边界 case；建议分 4 个子 commit（color / type / spacing / shape）便于回退。

---

### P0-2：字符串外化（594 → strings.xml）

**目标**：把所有 Composable 内 hardcode 的中文字符串抽到 `res/values/strings.xml`。

**步骤**：
1. 用脚本（grep + Python）一次性抽取所有 `"…中文字符…"` 到 `strings.xml`，生成 key（如 `screen_knowledge_title`、`action_import`）。
2. 替换 Composable 内 `Text("知识库")` → `Text(stringResource(R.string.screen_knowledge_title))`。
3. 删除 `app_name` 之外无用的 `strings.xml` 旧条目（若有）。

**对应发现**：
- `02-七维度评审.md` Pass 5（设计系统一致性）
- `01-系统盘点.md` §3.2（仅 1 个 string）

**估算**：人类 ~6h / CC ~20min（脚本生成 + 替换） + ~3h 校验。
**风险**：某些字符串是动态拼接的（如 `"基于「$itemTitle」的知识内容"`），需要 format 参数化。

---

### P0-3：正文字号提升到 14sp+（可访问性）

**目标**：所有作"正文/可读文字"用途的字号 ≥ 14sp；所有作"label"用途的 ≥ 12sp。

**步骤**：
1. 全 app 扫描 `fontSize = 10.sp` / `11.sp` / `12.sp` / `13.sp`。
2. 按上下文判断：若是"标签"（如"立即查看" / "继续整理" / "导入"）→ 升 12sp 或加粗。
3. 若是"正文"（如"自动化提炼后的成果" / "基于「...」的知识内容"）→ 升 14sp。
4. `14.sp` 已是合规下限，不必动；`15.sp` / `16.sp` 已是合规 body。

**对应发现**：
- `02-七维度评审.md` Pass 6.2（可访问性 4/10）
- `01-系统盘点.md` §4.2 字号表

**估算**：人类 ~3h / CC ~10min（半自动）+ ~2h 校验。
**风险**：字号提升会改变行高和卡片高度，可能引发 overflow；需要逐屏视觉验证。

---

### P0-4：动态颜色默认关闭

**目标**：`My_knowledgeTheme` 的 `dynamicColor` 默认值改为 `false`，避免 Android 12+ 设备上"壁纸色 + Ocean 蓝硬编码"两层系统冲突。

**步骤**：
1. 修改 `Theme.kt`：`dynamicColor: Boolean = false`。
2. 完整定义 `LightColorScheme` 和 `DarkColorScheme`，primary 用 `#147EC5` 系列。
3. 让"跟随系统主题色"作为 Settings 中的显式选项（默认 off）。

**对应发现**：
- `02-七维度评审.md` Pass 4（品牌不识别）
- `01-系统盘点.md` §2.2

**估算**：人类 ~1h / CC ~5min。
**风险**：几乎无；只是默认值变化。

---

## P1 — 应随下一轮主功能一起修（~3 人天）

### P1-1：抽出 `<StateContainer>` 和 `<EmptyState>` / `<ErrorState>` 组件

**目标**：每个 Screen 显式声明 Loading / Empty / Error / Success 四态。

**步骤**：
1. 在 `ui/component/` 下新增 `StateContainer.kt`，提供 `StateContainer(loading, empty, error, content)`。
2. 新增 `EmptyState(icon, title, actionLabel, onAction)` 组件。
3. 新增 `ErrorState(message, onRetry, onContactSupport)` 组件。
4. 改写 14+ 个缺空态的屏（见 `02-七维度评审.md` §2.1 表格）。

**对应发现**：Pass 2（状态覆盖 3/10）

**估算**：人类 ~8h / CC ~1h。

---

### P1-2：补全 Type scale（5 档语义）

**目标**：定义 5 档语义 type role：`caption / body / section / title / display`，每档对应一个 M3 typography token。

**步骤**：
1. `Type.kt` 中补全 `headlineLarge/headlineMedium/headlineSmall`、`titleLarge/titleMedium/titleSmall`、`labelLarge/labelMedium/labelSmall`。
2. 抽 `LocalTypography`（如果需要自定义）或直接用 `MaterialTheme.typography.*`。
3. 全 app 替换硬编码 `.sp` 为 `MaterialTheme.typography.*`。

**对应发现**：Pass 5（设计系统）

**估算**：人类 ~4h / CC ~30min。

---

### P1-3：暗色模式支持

**目标**：`isSystemInDarkTheme()` 实际生效，dark color scheme 完整定义。

**步骤**：
1. 在 `SemanticColor.kt` 中定义 `Palette` 的 light/dark 两套值。
2. 在 `Theme.kt` 中根据 `darkTheme` 选 `LightPalette` 或 `DarkPalette`。
3. 把 P0-1 抽出的 `LocalPalette` 用 `compositionLocalOf` 提供。

**对应发现**：Pass 4 / Pass 5

**估算**：人类 ~3h / CC ~15min。

---

### P1-4：图标系统统一

**目标**：删除 `KnowledgeComponents.kt:60-70` 的 `⌘` / `▦` Unicode 字形，统一用 Material Symbols。

**步骤**：
1. 引入 `androidx.compose.material:material-icons-extended`（如果尚未）。
2. 找到对应 Material 图标（"知识脉络" → `Icons.Default.Hub` 之类）。
3. 替换 `Text(iconText, ...)` 为 `Icon(imageVector = ...)`.

**对应发现**：Pass 4（ornamental icons）

**估算**：人类 ~2h / CC ~10min。

---

### P1-5：触摸目标最小 48dp

**目标**：所有可点击 Icon / TextButton 用 `Modifier.minimumInteractiveComponentSize()` 包裹（Compose 1.5+ Material 已提供）。

**步骤**：
1. 找到所有 `Modifier.size(16.dp)` / `Modifier.size(20.dp)` 的 Icon。
2. 外层加 `Modifier.minimumInteractiveComponentSize()` 或固定 `Modifier.size(48.dp)`。

**对应发现**：Pass 6.2

**估算**：人类 ~2h / CC ~15min。

## 任务依赖图

```
P0-1 (token)
  ├─ P1-2 (type scale)        ┐
  ├─ P1-3 (dark mode)         ├─ 都依赖 P0-1
  └─ P1-4 (icon)              ┘

P0-2 (strings) ─ 独立
P0-3 (font size ≥14sp) ── 依赖 P0-1 完成（统一 type 后批量改）
P0-4 (关闭 dynamic color) ─ 独立

P1-1 (StateContainer) ─ 独立
P1-5 (触摸目标 48dp) ─ 独立

P2-* 全部依赖 P0-* + P1-* 完成
```
