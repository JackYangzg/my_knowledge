## 关键问题（按优先级）

### P0（阻断可发布质量）

1. **设计系统未建立**：`Theme.kt` 的 M3 默认紫/粉与各 Screen 内 149+ 处 `Color(0xFF147EC5)` 蓝色硬编码并存，且 `dynamicColor = true` 默认值会让 Android 12+ 设备直接用壁纸色覆盖所有"硬编码"组件 → 视觉身份在每个设备上都不一样。
   - 影响：品牌不可识别；后续每个新屏都要"复制粘贴蓝色"。
   - 修复路径：见 `03-改进路线图.md` P0-1。

2. **字符串外化缺失**：`strings.xml` 仅有 3 条记录，**全部 23 个屏幕的中文文案都直接写在 Composable 里**。`i18n` 不可行，文案改一次要 grep 全部 UI 文件。
   - 修复路径：见 P0-2。

3. **正文字号低于 Android 可访问性推荐**：多处 `12.sp`、`13.sp` 用于"次要正文"，而 Material 3 + Android accessibility 推荐 `body` 文本 ≥ 14sp（最好 16sp），`label` 文本 ≥ 12sp 且不应用作正文。
   - 修复路径：见 P0-3。

### P1（应随下一轮主功能一起修）

4. **状态机未规格化**：空态、错误态、加载态、局部态在代码里只有"暂无知识库"一行灰字；其他屏空态缺位。
5. **Type system 不完整**：`Type.kt` 只定义了 `bodyLarge`；其他 12 个 M3 typography token 全部依赖默认值，硬编码 `.sp` 散落 9 种字号。
6. **图标系统分裂**：Material Icons 与 `⌘` / `▦` Unicode 字形混用（见 `KnowledgeComponents.kt:60-70`）。
7. **没有 dark theme 适配**：所有色值都是 light 假设；夜间用户拿到的是"白底黑字"。

### P2（机会型改进）

8. AI 信任标记 `【来自原文】` `【AI推理】` `【信息不足】` 是显著差异化功能，但目前仅 README 提及，UI 实现散落；建议提取为统一组件。
9. 知识脉络图渲染（曾用 AntV G6）被移除 — 核心差异化功能之一缺位。
10. Settings 屏一个文件 531 行承载 14+ 模型配置项 — 拆为 provider-specific wizard。

## 与"主流 Android 应用"的差距

| 主流期望 | 本项目现状 | 差距 |
|---------|---------|------|
| Material 3 完整 token 体系 | 仅声明 Purple/Pink 两套 fallback，实际未使用 | 严重 |
| 12dp/16dp/24dp 节奏的 spacing scale | 直接硬编码 `8/12/14/16/20/22/24/28` dp 散落 | 严重 |
| 完整 typography scale (12/14/16/22/...) | 9 种字号、5 种字重、零 token 化 | 严重 |
| 颜色语义化 (primary/secondary/surface/error) | 28+ 硬编码颜色，无命名 | 严重 |
| dynamic color 仅作为 opt-in 增强 | 默认开启且被硬编码绕过 | 中 |
| 字符串外化 (i18n ready) | 3 / ~1500+ 条字符串 | 严重 |
| 触达目标 ≥ 48dp | 多处 16dp 按钮 | 中 |
| body 文字 ≥ 14sp | 多处 12-13sp | 中 |
| Loading / Empty / Error 三态齐备 | 仅 Empty 偶有 | 严重 |
| 一致的导航 back/forward 语义 | 14 个屏各自处理返回 | 中 |

## 建议路线

- **第一步（P0，约 2 人天）**：抽出 design token、字符串外化、正文字号提升 → 单一 PR，重构性 commit。
- **第二步（P1，约 3 人天）**：补齐状态机、typography、dark theme、icon 系统。
- **第三步（P2，约 2 人天）**：差异化功能（AI 信任标记组件化、知识脉络图回填、Settings 重构）。
