# 02 — 七维度评审

> 七维度框架来自 gstack `plan-design-review` skill：IA / States / Journey / AI Slop / Design System / a11y / Unresolved。
> 每一维度按 **评分 → 主要问题 → 修复建议** 顺序展开。
> 适用规则集：**App UI**（工具类、数据密集、任务驱动），非 MARKETING 页面。

## Pass 1 — 信息架构 (IA)

**评分：6/10**

### 现状

- 23 个 Screen 文件 + 1 个根 `KnowledgeApp.kt` 集中管理 `NavHost`。
- 顶层 `KnowledgeScreen`（知识库首页）作为主入口；其他屏通过 `onOpenKbDetail` / `onOpenContext` / `onOpenFragments` 等回调跳转。
- `KnowledgeApp.kt` 中集中注册 14 个 `composable(...)` 路由。

### 问题

1. **导航入口分散**：`KnowledgeScreen` 内含 "导入" 文本按钮（`KnowledgeScreen.kt:75-89`），但真正的"导入中心"通过 `ImportCenterScreen` 单独存在；`InspirationScreen` 又是另一条独立路径。**三条进入"添加内容"的路径**，没有任何提示哪个是主路径。
2. **底部 tab 缺失**：`KnowledgeApp.kt` 没有底部 `NavigationBar`，所有跳转靠卡片和按钮完成。Material 3 工具类应用的标准范式是 `NavigationBar` + 3-5 个顶层目的地。当前是"卡片式 Hub + 散落跳转"范式。
3. **返回语义不统一**：`AskScreen` 自定义返回按钮（`AskScreen.kt:61-74`），`SettingsScreen` 自定义返回，根 `NavHost` 用系统返回。用户在"自定义返回按钮的屏"和"无自定义的屏"之间会得到不同反馈。
4. **无 search / global entry**：23 个屏没有全局搜索入口（虽然数据层有 `SearchDao` + FTS4）。"想找东西"是知识管理类 App 的最高频诉求，但**入口被埋没**。

### 修复建议（10/10 是什么样）

- 顶层加 `NavigationBar`（3 tab：知识 / 灵感 / 我的；或 4 tab：知识 / 导入 / 灵感 / 我的），"导入"作为 tab 而不是按钮。
- 全局 `SearchBar` 顶置（任何屏可下拉召唤）。
- 统一返回处理（用 `BackHandler` + NavController 集中管理）。
- 主页 Hub 保留，但**降级为"摘要卡片"角色**而非导航根。

## Pass 2 — 交互状态覆盖

**评分：3/10**

### 现状

详见 `01-系统盘点.md` §6：5 屏有 loading，3 屏有 empty，2 屏有 error，**0 屏有 partial 状态**。

### 关键问题

#### 2.1 缺空态的屏

| Screen | 是否处理空态 | 影响 |
|--------|------------|------|
| `InspirationScreen` | ❌ | 用户没有灵感时会看到一张白屏 |
| `KnowledgeDetailScreen` | ❌ | 知识库为空时没有引导 |
| `KnowledgeEditorScreen` | ❌ | 编辑中的内容丢失提示缺位 |
| `RecycleBinScreen` | ❌ | 回收站为空时白屏 |
| `ReviewQueueScreen` | ❌ | 审核队列为空时白屏 |
| `ImportCenterScreen` | ❌ | 没有任何导入时白屏 |
| `AskScreen` | ❌ | 首次进入 AI 对话没有引导消息 |
| `SubScreens`（含多个子屏） | ❌ | 多个子屏零空态 |

#### 2.2 缺错误态的屏

- 几乎所有屏都没有 `Snackbar` / `Banner` / `errorMessage` 字段。
- 仅有 `ProcessingStatusScreen.kt` 渲染 `task.errorMessage` —— 这是加工任务列表，对"AI 调用失败"是合理的；但**最终用户层的错误反馈**（如 AskScreen 调 LLM 失败）缺位。

#### 2.3 缺 loading 状态语义

- `CircularProgressIndicator` 出现 5+ 文件，但都是"硬塞一个圆圈"，没有：
  - skeleton loading（卡片骨架）
  - 进度百分比（加工任务有 `task.progress`，但 UI 上没渲染）
  - 取消能力

#### 2.4 状态规格表（修复目标）

| Screen | Loading | Empty | Error | Success | Partial |
|--------|---------|-------|-------|---------|---------|
| KnowledgeScreen | 骨架卡片 | "还没有知识库，导入第一份文件开始沉淀" + 主行动 | Snackbar 顶部条 | 已实现 | 知识库列表分页加载 |
| InspirationScreen | 卡片骨架 | "灵感池等待第一批想法..." + "新建灵感" | Snackbar | 已实现 | 滚动加载更多 |

| KnowledgeEditorScreen | 保存按钮 spinner | "内容为空无法保存"（已隐含） | 顶部 Banner | 已实现 | 自动保存状态指示器 |
| ImportCenterScreen | 步骤进度条 | "选择文件开始" | 失败任务可重试 | 已实现 | 多文件并行进度 |
| RecycleBinScreen | 列表骨架 | "回收站是空的" + emoji | 不可恢复时 Snack | 已实现 | 滚动加载 |

### 修复建议

- 抽出 `<StateContainer loading={} empty={} error={} content={}>` 组件，**强制每个 Screen 显式声明 4 个状态**。
- 抽出 `<EmptyState icon title action />` 组件统一空态：含暖意文案 + 主行动 + 上下文。
- AI 失败必须可重试，且**指向解决方案**（"换模型"或"检查网络"），而不是空白错误码。

## Pass 3 — 用户旅程 & 情绪弧

**评分：5/10**

### 现有可识别的情绪设计

**亮点：AI 信任标记系统**

README 中承诺：
> AI 回答自带可信标记：`【来自原文】` `【AI推理】` `【信息不足】`，用户始终知道信息源头

这是 **罕见的、能解决"AI 幻觉恐慌"的设计**。在同类知识管理 App 中大多是亮点（Notion AI、飞书 AI、豆包都没有同等显式标注）。

### 主要旅程 & 情绪缺口

#### 旅程 A：第一次打开 App（5 秒第一印象）

- 进入 `KnowledgeScreen`：白底、Ocean 蓝小色块、列表。
- 5 秒内：用户看到 "知识库 / 少打扰，多沉淀" 标题 + "知识整理" 区块 + 知识库列表。
- **情绪：中性偏冷漠**。没有"欢迎"，没有"今天我可以帮你做什么"。

#### 旅程 B：导入第一个文件（关键的"魔法时刻"）

- 点击"导入" → `filePickerLauncher.launch(...)` 选文件 → `selectedFileUris` 状态 → `showImportSheet = true`。
- 弹出 `ImportSheet`。
- **情绪：OK，但缺乏期待感**。"导入" 后没有进度反馈；用户不知道会发生什么。
- README 承诺"两阶段摄入"是核心卖点，但 UI 上没有"加工中..."的友好引导（虽然在 `ProcessingStatusScreen` 里有，但普通用户不一定去那里看）。

#### 旅程 C：加工完成，看到 AI 提炼

- 用户期待：看到"摘要 / 标签 / 归档建议 / 脉络演进"。
- 实际：要去 `KnowledgeDetailScreen` 才看得到。**没有"加工完成"主动通知**（push 通知 / In-app banner）。

#### 旅程 D：向 AI 提问

- 入口：`AskScreen`。
- 体验：基础聊天界面，**流式响应**（README 提到"AI Gateway 暴露 completeObserved / chatJsonObserved"）。
- **情绪：合理**，但失败处理粗糙。

### 修复建议

- **第一印象**：首启弹"3 个引导气泡"（不要全屏 onboarding），告诉用户核心价值（少打扰 / AI 信任）。
- **导入完成通知**：加工完成 → 触发本地通知 + In-app banner（"你的笔记已加工完成，[查看]"）。
- **AI 回答置信度视觉化**：当前 `【来自原文】` 是文字，建议加颜色编码（来自原文 = 蓝、AI 推理 = 橙、信息不足 = 灰）。
- **空态暖意**：每个空态都说"为什么空 + 怎么变不空"，而不是"暂无"。

## Pass 4 — AI Slop 风险

**评分：5/10**

### 适配规则集：App UI

按 gstack `plan-design-review` 的"Design Hard Rules"分类，本项目是 **APP UI**（工具类、数据密集、任务驱动），不应用 MARKETING 规则。

### 强制拒绝检查

| 规则 | 是否触发 | 说明 |
|------|--------|------|
| 1. 通用 SaaS 卡片网格作为首屏 | ❌ | 主页不是 3 列 feature grid |
| 2. 美图 + 弱品牌 | ❌ | 无大图 |
| 3. 强标题 + 无清晰 CTA | ⚠️ | "知识库 / 少打扰，多沉淀" 有标题但 CTA 弱（仅右上"导入"） |
| 4. 文字背后是忙碌图像 | ❌ | 无图 |
| 5. 多区段重复同一情绪句 | ❌ | — |
| 6. 轮播图无叙事目的 | ❌ | 无轮播 |
| 7. App UI 用堆叠卡片代替布局 | ⚠️ | 主页 "知识整理" 是 2 列卡片 + 知识库列表卡片化。卡片偏多 |

### Litmus 检查

| 检查 | 结果 | 说明 |
|------|------|------|
| 1. 品牌在第一屏不可错过 | ❌ | 无 logo / 品牌色身份；Ocean 蓝与壁纸色无差别 |
| 2. 一个强视觉锚点 | ❌ | 第一屏无视觉锚（最显眼的只是标题文字） |
| 3. 仅扫标题即可理解页面 | ✅ | "知识库" / "知识整理" / "我的知识库" 一目了然 |
| 4. 每区段一个 job | ✅ | 主页各 section 职责清晰 |
| 5. 卡片确有存在必要 | ⚠️ | `DigestCard` 是真有交互（点击跳转），OK；`QuietCell` 列表行也 OK |
| 6. 动效提升层次或氛围 | ❌ | 全 app **无显式动效规格**（`animate*AsState` / `AnimatedContent` 等搜索量极低） |
| 7. 去除装饰阴影仍有高级感 | ⚠️ | 当前 1dp border + 2dp shadow 是主要质感来源 |

### App UI 规则符合性

| 规则 | 符合度 | 现状 |
|------|-------|------|
| Calm surface hierarchy | ⚠️ | 多层 Surface + 边框，层次偏"装饰" |
| Strong typography | ❌ | 无完整 type scale |
| Few colors | ❌ | 30+ 硬编码 |
| Dense but readable | ✅ | 列表密度合理 |
| Minimal chrome | ⚠️ | 主页有 PageHeader + 卡片 + 列表，chrome 中等 |
| Avoid dashboard-card mosaics | ⚠️ | 主页略有此倾向 |
| Thick borders | ❌ | 1dp border 全 app 滥用 |
| Decorative gradients | ✅ | 无 |
| Ornamental icons | ❌ | 36dp 彩色背景 + Unicode ⌘/▦ 算装饰性 |
| Cards only when card IS the interaction | ⚠️ | 大部分 OK，但 `KnowledgeDigestSection` 是装饰性卡片 |
| Section headings state area or action | ✅ | "我的知识库" / "知识整理" 命名清楚 |

### 修复建议

- **去掉 1dp 边框**（所有 `BorderStroke(1.dp, ...)`），改用 elevation / surface tint 表达层次。
- **重做"知识整理"区块**：不要 2 列卡片，改成 inline summary（如"23 条灵感 / 5 份文件待加工"），更轻量。
- **加品牌色锚点**：例如 App 启动瞬间显示 1 个 logo splash（200ms），让用户建立"这是 my_knowledge" 的肌肉记忆。
- **加显式 motion**：页面进入用 `AnimatedContent`、加工完成用 `Lottie` 或 `AnimatedVisibility`。

## Pass 5 — 设计系统一致性

**评分：2/10**

### 现状

- 无 `DESIGN.md`（`find . -name "DESIGN.md"` 返回空）。
- 无 typography scale token。
- 无 spacing scale token。
- 无 color semantic token。
- 无 shape scale token。
- 无 motion / animation duration token。
- `Theme.kt` 中 M3 `ColorScheme` 仅 fallback，几乎不参与实际渲染。

### 关键问题

#### 5.1 颜色 Token 缺失

详见 `01-系统盘点.md` §4.1。30+ 硬编码颜色散落 1000+ 次。

具体例子：`Color(0xFF147EC5)` 出现 149 次，分布在 19 个文件中。任何"主色变更"都要全 app 替换。

#### 5.2 字体 Token 缺失

`Type.kt` 只定义 `bodyLarge` 一个 token。其它 12 个 M3 typography token 全部回落到 M3 默认值，而**实际 UI 中直接 hardcode `.sp`**（13+ 种），根本不用 `MaterialTheme.typography.*`。

例子（`KnowledgeComponents.kt:46-49`）：
```kotlin
Text("知识整理", fontSize = 14.sp, fontWeight = FontWeight.Medium, color = Color(0xFF737373))
Text("自动化提炼后的成果", fontSize = 12.sp, color = Color(0xFFA3A3A3))
```

#### 5.3 间距 Token 缺失

`01-系统盘点.md` §4.3 显示 4dp 节奏基本存在但无 token。

#### 5.4 形状 Token 缺失

`RoundedCornerShape(12.dp)` / `RoundedCornerShape(16.dp)` / `RoundedCornerShape(8.dp)` 散落，没有 `MaterialTheme.shapes.*` 的统一使用。

#### 5.5 暗色模式缺失

`Theme.kt` 有 `darkColorScheme(...)` 但**仅作为 dynamic color 不可用时的 fallback**。如果用户禁用 dynamic color（如 `dynamicColor: Boolean = false`），所有硬编码 `Color(0xFF147EC5)` 在 dark mode 下依然是浅蓝，**在深色背景上对比度过高、刺眼**。

### 修复建议（10/10 应有的状态）

```kotlin
// 推荐结构
ui/theme/
├── Color.kt           // 品牌色 + 中性色（保持 Hex 集中）
├── SemanticColor.kt   // Primary/Secondary/Error/Warning/Info 命名层
├── Type.kt            // 完整 13 个 typography token
├── Spacing.kt         // xs/sm/md/lg/xl/2xl + contentPadding
├── Shape.kt           // small/medium/large corner radius
├── Motion.kt          // durationShort/Medium/Long + easing
└── Theme.kt           // 用上述 token 组装 M3 ColorScheme/Typography/Shapes
```

抽出 `LocalSpacing` / `LocalPalette` 等 `CompositionLocal`，让 Composable 用 `LocalPalette.current.brand` 而不是 `Color(0xFF147EC5)`。

## Pass 6 — 响应式 & 可访问性

**评分：4/10**

### 6.1 响应式

#### 现状

- 没有 `WindowSizeClass` 判断。
- 没有 `Modifier.aspectRatio()` / `BoxWithConstraints` 等响应式布局。
- 没有平板 / 横屏 / 折叠屏适配代码。

#### 问题

- 主页"知识整理"2 列卡片在 360dp 窄屏上拥挤（卡片高度 156dp + 36dp icon + 多行文字）。
- `InspirationScreen.kt:1030 lines`（最长屏）几乎肯定是"所有内容一屏到底"，大屏浪费大量空间。

#### 修复建议

- 引入 `androidx.compose.material3:material3-window-size-class`。
- 窄屏：1 列；中屏：2 列；宽屏：3 列 + 侧栏。
- `InspirationScreen` 这种长屏要支持 tab 切换或 anchor 导航。

### 6.2 可访问性

#### 字号问题

详见 `01-系统盘点.md` §4.2。**多次使用 10.sp / 11.sp / 12.sp / 13.sp 作为正文**：

| 字号 | 出现次数 | 是否合规 |
|------|---------|---------|
| 10.sp | 13 | 严重低于 Material 推荐的 12sp 最小尺寸 |
| 11.sp | 52 | 略低，勉强可作 label |
| 12.sp | 74 | 边界，可作 label 不可作 body |
| 13.sp | 49 | 低于 Material 推荐的 14sp 最小 body |
| 14.sp | 60 | body 最小 |

Material 3 + Android Accessibility 推荐：**body 文本 ≥ 14sp，label 文本 ≥ 12sp，且不用 12sp 以下作 label**。

#### 触摸目标问题

- `AskScreen.kt:69` Icon size `16.dp`。
- 多个返回按钮 `Modifier.height(24.dp)`。

Material 3 推荐：触摸目标 ≥ 48 × 48 dp。**当前多处远低于 48dp**。

#### 屏幕阅读器适配

- 很多 `Icon(... contentDescription = null)` —— 装饰性图标 null 是 OK 的。
- 但部分功能图标 `contentDescription = null` 而**承载了关键功能**（如 `Icons.Default.FileUpload` 没有朗读"导入"）。
- 没有 `Modifier.semantics { ... }` 自定义语义。

#### 颜色对比度

Ocean 蓝 `#147EC5` 在白底上对比度 ~5.5:1（**仅在 ≥ 18px 或加粗时通过 WCAG AA**）；用于 14sp 文字时勉强可用，但需要验证。白底黑字 `#0F172A` 对比度 ~17:1，OK。

#### 焦点指示

- 没有显式 `focusRequester` / `focusable()` 处理。
- Tab 键 / D-pad 用户（Android TV、外接键盘）体验未知。

### 修复建议

- **P0**：把 `11.sp` / `12.sp` / `13.sp` 的"正文"全部提升到 `14.sp`，把 `10.sp` 提升到 `12.sp`（仅保留作纯装饰数字 / 角标）。
- **P0**：所有可点击 Icon 加 `Modifier.minimumInteractiveComponentSize()` 包裹（Compose 1.5+ Material 已提供）。
- **P1**：所有功能 Icon 加 `contentDescription`，装饰 Icon 保持 null。
- **P1**：增加焦点指示（`Modifier.focusable()` + `focusIndication`）。
- **P2**：引入 `WindowSizeClass` 适配大屏。
