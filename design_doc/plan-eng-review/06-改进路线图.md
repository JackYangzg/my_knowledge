## 2. P0 路线（5 天）

### 2.1 P0-1: 拆 `IngestOrchestrator` 为 4 个聚焦组件（3 天）

**目标**：把 2793 行单类拆为 4 个 ≤ 600 行的组件

**步骤**：
1. **抽 `IngestPipeline` 接口**（4 阶段抽象）
   ```kotlin
   interface IngestPipeline {
       suspend fun parse(task: ProcessingTaskEntity): Result
       suspend fun analysis(task: ProcessingTaskEntity): Result
       suspend fun generation(task: ProcessingTaskEntity): Result
       suspend fun embedding(task: ProcessingTaskEntity): Result
   }
   ```

2. **抽 `IngestScheduler` 4 轨并行**（独立类，约 400 行）
   - 移出 `runUntilIdle`, `shouldClaimNextSameSourceTask`, `withLocks`
   - 暴露 `runUntilIdle(maxTasks, parallelism)`
   - 测试可独立 mock

3. **抽 `IngestStateMachine` 状态转换**（约 200 行）
   - `transitionTo(taskId, newStatus): Result<Unit>`
   - 集中校验合法性

4. **抽 `IngestCache`**（约 150 行）
   - `isIngestCacheHit(sha256, promptVersion): Boolean`
   - `recordCacheHit(sha256, promptVersion, resultId)`
   - 修复 ARCH-6（cache key 含 promptVersion）

5. **`IngestOrchestrator` 缩为 facade**（约 200 行）
   - 仅协调上述 4 个组件
   - 对外 API 不变

**验收**：
- `IngestOrchestrator` ≤ 800 行
- 现有所有调用方零修改
- 4 轨并行的单测可达（带 fake `IngestPipeline`）

**风险**：回归风险中等。建议分两步：先抽 `IngestScheduler`，再抽其他 3 个。

### 2.2 P0-2: 抽 `toAiException(scope, e)` 统一 `AiGateway` 错误处理（2 天）

**目标**：删除 `AiGateway` 4 处重复 try/catch

**步骤**：
1. 在 `AiGateway` 文件内（或 `data/ai/error/` 抽包）定义：
   ```kotlin
   internal fun Throwable.toAiException(scope: String): AiException = when (this) {
       is AiException -> this
       is UnknownHostException -> AiException("[$scope][DNS 失败] ${message}", this)
       is SocketTimeoutException -> AiException("[$scope][超时] ${message}", this)
       is SSLException -> AiException("[$scope][SSL 错误] ${message}", this)
       is IOException -> AiException("[$scope][连接失败] ${message}", this)
       else -> AiException("[$scope][未知错误] ${message}", this)
   }
   ```

2. 4 处调用方改为：
   ```kotlin
   try { ... } catch (e: Throwable) { throw e.toAiException("streamJson") }
   ```

3. 写单测覆盖 5 个分类（DNS/超时/SSL/IO/未知）

**验收**：
- `AiGateway` ≤ 600 行（减重 ~200 行）
- 错误消息一致
- 5 个分类各自有 unit test

**风险**：低。仅是重构，行为不变。

## 8. 不在路线图中的项

下列项**有意延后**（或永久不做）：
- 全部 entities 重构（ARCH-4）：ROI 低，等真需要查询 `*Json` 列时再做
- 真语义向量（PERF-6）：5+ 天工，依赖端侧模型集成，价值待验证
- `IngestQueuePolicy` 内联（CQ-2）：8 行代码，独立文件无害
- Summary/Tag/Archive 旧管线（P2-1）：保持可达到以备不时之需
