# 业务流程全景

> 用 ASCII 数据流图描述本工程的三大业务流程：
> 1. 文档/笔记摄入管线（核心，4 阶段 + 4 轨并行）
> 2. 灵感脉络增量更新（LLM 优先 + 启发式兜底）
> 3. 知识库跨库迁移（带 KB 写锁）

## 1. 摄入管线（核心）

### 1.1 入口与触发

```
┌────────────────────────────────────────────────────────────────┐
│ 用户操作                                                       │
│   - NoteEditor 保存 → NoteEditorViewModel.saveToKnowledgeBase │
│   - 导入面板 → IngestQueueService.enqueueSource               │
│   - 重试入口 → KnowledgeRepositoryImpl.retryProcessingForSource│
└────────────────────────┬───────────────────────────────────────┘
                         │ suspend
                         ▼
        ┌────────────────────────────────────┐
        │ ProcessingTaskScheduler            │
        │   .scheduleIngestQueue()           │
        └────┬───────────────────────────────┘
             │ ① 启动 IngestRuntime.start(ctx)
             │ ② WorkManager.enqueueUniqueWork("ingest_queue", KEEP)
             ▼
   ┌──────────────────────────────────────────┐
   │ IngestRuntime (process-scope coroutine)  │
   │   - PowerManager.WakeLock (6h)           │
   │   - WifiManager.WifiLock                 │
   │   - runMutex.withLock { ... }            │
   └────┬─────────────────────────────────────┘
        │ 串行 do { runOnceInternal } while (rerunRequested)
        ▼
   ┌────────────────────────────────────────────┐
   │ IngestOrchestrator.runUntilIdle()          │
   │   ① resetInterruptedTasks()               │  进程启动恢复
   │   ② recoverSourcesWithoutActiveTasks()    │
   │   ③ while (有任务) {                       │
   │        拉一批 (maxTasks=8)                 │
   │        按 kbId 分桶 → 同 KB 串行           │
   │        按 sourceId 分桶 → 同源链式         │
   │        4 轨并发执行 (parallelism=4)         │
   │      }                                     │
   └────┬───────────────────────────────────────┘
        │ 单元: task = runTask(item)
        ▼
   ┌────────────────────────────────────────────┐
   │ IngestOrchestrator.runTask()               │
   │   按 task.type 分发:                       │
   │     "parse"       → parseTask()            │
   │     "analysis"    → analysisTask()         │
   │     "generation"  → generationTask()       │
   │     "embedding"   → embeddingTask()        │
   │   每个 task:                               │
   │     shouldClaimNextSameSourceTask() ?      │ ← IngestQueuePolicy
   │       是 → 同源同 KB 链式 (无锁)            │
   │       否 → withLocks(kbLock) { ... }       │
   └────────────────────────────────────────────┘
```

### 1.2 4 阶段管线

```
┌─────────────────────────────────────────────────────────────────┐
│ Stage 1: parse (本地)                                           │
│   输入:  SourceDocumentEntity (sha256)                          │
│   动作:  选 parser: MarkdownParser / PdfParser / ImageOCR / ...  │
│         写 ParsedContentEntity + KnowledgeFragmentEntity[]      │
│   输出:  enqueue("analysis", {parsedContentId, sourceId})       │
│   异常:  写 ProcessingTaskLogEntity (level=ERROR)               │
│   缓存:  isIngestCacheHit(sha256) → skip analysis + generation │
└────────────────────────┬────────────────────────────────────────┘
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│ Stage 2: analysis (LLM 同步 JSON-mode)                          │
│   输入:  ParsedContent.markdown                                 │
│   路径:  if (markdown.length > 50_000)                          │
│           requestAiAnalysisLongSource()  ← chunked + checkpoint │
│         else                                                    │
│           chatJson(system, user)                                │
│   输出:  AnalysisResultEntity (summary, tags, entities,         │
│          concepts, relations, claims, gaps, archiveRec)         │
│   异常:  retry: AiGateway.retryRemoteCall (3 次, 指数退避)     │
│   进度:  sample(15 chars) 写入 ProcessingTaskEntity.progress    │
└────────────────────────┬────────────────────────────────────────┘
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│ Stage 3: generation (LLM 流式 JSON-mode / 文本流)               │
│   输入:  AnalysisResult + ParsedContent.markdown                │
│   动作:  调 AiGateway.streamJsonWithThrottledProgress()         │
│         按 FILE: <path>\n<content>\nEND_FILE 切块              │
│   写回:  mergeWikiPageMarkdown / mergeListingPage (section-aware)│
│   收尾:  schedulePostGenerationRebuilds()                       │
│           ├ RebuildDebouncer.scheduleGraphRebuild(kbId)         │
│           ├ RebuildDebouncer.scheduleOverviewRefresh(kbId)      │
│           ├ RebuildDebouncer.scheduleSweepReviews(kbId)         │
│           └ RebuildDebouncer.scheduleThreadEvolution(kbId)      │
│   取消:  ensureActive() per SSE line                            │
└────────────────────────┬────────────────────────────────────────┘
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│ Stage 4: embedding (本地 16 维 hash-bucket)                     │
│   输入:  KnowledgeFragmentEntity[]                              │
│   动作:  rebuildFragmentsForItem(item) → 16 维 localEmbedding    │
│   写回:  KnowledgeEmbeddingEntity                               │
│   注意:  这是占位 embedding，不是真向量。语义搜索走 LIKE 而非 cosine │
└─────────────────────────────────────────────────────────────────┘
```

### 1.3 4 轨并行模型（关键并发点）

```
       runUntilIdle 拉一批 (size ≤ 8)
                       │
        ┌──────────────┼──────────────┐
        │              │              │
   Lane 0 (IO)    Lane 1 (IO)    Lane 2 (IO)    Lane 3 (IO)
        │              │              │              │
   ┌────▼────┐    ┌────▼────┐    ┌────▼────┐    ┌────▼────┐
   │ 抢任务  │    │ 抢任务  │    │ 抢任务  │    │ 抢任务  │
   │ 同源链式│    │         │    │         │    │         │
   │ 同 KB  │    │         │    │         │    │         │
   │ 持锁   │    │         │    │         │    │         │
   └────┬────┘    └────┬────┘    └────┬────┘    └────┬────┘
        │              │              │              │
        └──────────────┴──────┬───────┴──────────────┘
                              │ AtomicInteger inFlight--
                              ▼
                       if (inFlight == 0) 再拉一批

关键不变量:
  - 同一 sourceId 任务链式: parse → analysis → generation
    由 IngestQueuePolicy.shouldClaimNextSameSourceTask 控制
  - 同一 kbId 写锁: withLocks(kbId) { } 包住 wiki 页面合并
  - 跨 KB 完全并行
```

### 1.4 缓存命中与重启恢复

```
进程启动:
  IngestOrchestrator.runUntilIdle()
    │
    ├─ ① resetInterruptedTasks()
    │   UPDATE processing_task SET status='pending'
    │   WHERE status IN ('running', 'interrupted')
    │     AND startedAt < now - 5min    ← 僵尸任务清理
    │
    └─ ② recoverSourcesWithoutActiveTasks()
        SELECT source.* WHERE 没有 in-flight task
        AND (status='parse' OR status='analysis' OR status='generation')
        → 重新 enqueue(task.type)

缓存命中 (Stage 1 之后):
  isIngestCacheHit(sha256):
    SELECT llm_wiki WHERE sha256 = :sha256
    if (存在) → 跳到 Stage 4 (embedding)

长源 checkpoint (Stage 2 内部):
  LongSourceCheckpointStore(filesDir/<sha256>.json)
    { chunkIndex, partialEntitiesJson }
  崩溃后启动: 从最后一个 chunkIndex 续跑
```

## 2. 灵感脉络增量更新

```
用户保存灵感
    │
    ▼
NoteEditorViewModel.saveToKnowledgeBase
    │
    ▼
ProcessingTaskScheduler.scheduleLlmThreadUpdate(kbId, newItemId)
    │
    ▼
WorkManager.enqueueUniqueWork("llm_inspiration_thread_$kbId", REPLACE)
    │
    ▼
LlmInspirationThreadWorker.doWork()
    │
    ├─ ① KnowledgeRepository.getInspirationContext(kbId, newItemId)
    │     { newInspiration, historicalInspirationDigest(30),
    │       existingThread (knowledge_thread where kbId=?) }
    │
    ├─ ② computeInputHash(ctx) ← SHA-256
    │   if (existing.inputHash == inputHash) return Result.success()  // 跳过
    │
    ├─ ③ AiGateway.chatJson(systemPrompt, userPrompt, THREAD_JSON_SCHEMA)
    │   │
    │   ├─ 成功 → parseThreadJson(raw) → ParsedThread
    │   │         buildThreadEntity(existing, kbId, inputHash, generated)
    │   │         buildThreadLogEntity(... DIFF_SENTINEL blob ...)
    │   │
    │   └─ 失败 / 解析失败 / apiKey 为空
    │         → buildFallbackThread(...)  // 启发式 tag 聚类
    │
    ├─ ④ repository.saveThread(thread)
    ├─ ⑤ repository.appendThreadLog(log)
    └─ ⑥ repository.updateBase(base.copy(threadStatus="ready"))
```

## 3. 知识库跨库迁移

```
用户操作: NoteEditorScreen / KbManager 调
KnowledgeRepositoryImpl.moveItemToBase(itemId, fromKbId, toKbId)
    │
    ▼
事务 (Room @Transaction):
  ① loadItem(itemId)
  ② loadBase(toKbId)            ← 校验目标存在
  ③ moveItemToBase             ← update knowledge_item
  ④ rebuildGraphForBase(toKbId) ← 重建目标 KB 图（增量）
  ⑤ schedulePostGenerationRebuilds(toKbId)  ← 触发去抖
  ⑥ scheduleIngestQueue()      ← 触发 embedding 重算

异常处理: try/catch → 记 Log.e → throw e
  // ⚠ P1-5: try/catch 仅用于日志，没有 swallow
  // 优点: 错误不被吞，调用方感知
  // 缺点: 错误信息没增强，只是 re-throw
```

## 5. 后台调度全景

```
                  ┌───────────────────────┐
                  │ WorkManager (KEEP)    │ ← 进程被杀后恢复
                  │   "ingest_queue"      │
                  │   → IngestWorker      │ ← 20 行包装
                  │      → IngestRuntime.runOnce() │
                  └───────────────────────┘
                            ▲
                            │ EnqueueUniqueWork (KEEP)
                            │
       ┌────────────────────┴─────────────────────┐
       │                                          │
┌──────▼──────────┐                    ┌──────────▼─────────┐
│ IngestRuntime   │                    │ LlmInspiration-    │
│ (object)        │                    │ ThreadWorker       │
│ - process scope │                    │ - per-KB unique    │
│ - wake/wifi     │                    │   REPLACE          │
│ - runUntilIdle  │                    │ - 每次新增灵感触发 │
└──────┬──────────┘                    └────────────────────┘
       │
       │ 完成后
       ▼
 RebuildDebouncer (per-KB)
   ┌──────────────┐
   │ scheduleGraph │ debounce 1s  │ → rebuildGraphForBase
   │ scheduleOverview │ debounce 1s │ → refreshOverviewForBase
   │ scheduleSweep │ debounce 3s  │ → SweepReviews.sweep
   │ scheduleThread│ debounce 5s  │ → ThreadEvolutionRunner.runEvolution
   └──────────────┘
       │
       │ 每个 kb+kind 独立 Bucket
       │ ConcurrentHashMap<String, Bucket>
       │   Bucket { trigger: SharedFlow, job: Job? }
       │
       ▼
   collectLatest { try { action() } catch Log.e }

⚠ P1-3: catch (Throwable) → Log.e → swallow
   一致性问题: 同一 KB 持续失败 → 永远显示旧数据
```
